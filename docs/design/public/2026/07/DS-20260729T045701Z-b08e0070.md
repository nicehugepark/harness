## 요약

`ids.slugify()` 의 슬러그 정규화 로직을 `harness/lib/harness_core/textutil.py` 의
`normalize_title()` 로 **이관**하고, `ids.slugify` 를 얇은 위임으로 남기며, 경계
조건을 시험으로 고정하는 설계입니다. 검증 기준 5항을 **제1판**으로 동결합니다.

### 이 설계의 척추 — 이관이지 개선이 아니다

`normalize_title()` 의 관측 동작은 현행 `ids.slugify()` 와 **전 입력에서 동일**해야
합니다. 조사 중 개선 여지를 여럿 발견했지만(§범위 밖) **한 건도 이번에 손대지
않습니다.** 이유는 두 가지입니다.

1. 원장 `why` 가 "파이프라인 완주를 실물로 확인할 **작고 닫힌** 요청"이라고
   목적을 명시했습니다. 범위를 넓히면 목적 자체가 훼손됩니다.
2. 동작을 바꾸지 않으면 기존 `test_ids.py` 의 슬러그 시험 3건이 **자동 회귀
   감지기**가 됩니다. 동작을 함께 바꾸면 그 감지기를 잃고, 실패 시 원인 절단면이
   `ids` · `paths` · `gate` · `envelope` 4계층으로 넓어집니다.

### 설계 판단 정정 — 초기 가설을 폐기했습니다

착수 시 저는 `normalize_title` 을 "제목 정규화"(공백 접기 + 비ASCII **보존** +
NFC 적용)로 설계했습니다. **이 가설은 틀렸고 폐기합니다.** 원장 요약이
"문자열을 **문서 슬러그로** 정규화하는 함수"라고 못박고 있고, 설계 정본
`DS-20260728T184100Z-25404613` L218 이 비ASCII 처리를 이미 확정해 두었기
때문입니다 — 원문 인용:

> 비ASCII 제목(한글 등)은 로마자 변환을 시도하지 않는다: 플랫폼별 유니코드
> 정규화 차이가 파일명 축에 들어오는 것을 원천 차단한다(S§4.3 실행 환경 불문).

즉 비ASCII 는 **보존이 아니라 제거**(하이픈 치환)이고, NFC 적용은 정본에 없는
동작이므로 배제합니다. 함수명의 `title` 은 **입력**이 제목이라는 뜻이지 출력이
제목 형태라는 뜻이 아닙니다.

## 조사 결과 — "흩어져 있다"의 실제 형태

원장 요약은 정규화 함수가 "여러 자리에 흩어져 있다"고 합니다. 전수 조사 결과
**문서 슬러그를 만드는 정식 함수는 1개뿐**입니다. 흩어진 것은 함수가 아니라
**"슬러그화해야 하는데 하지 않는 자리"** 입니다.

| # | 위치 | 성격 | 공백 | 대소문자 | 비ASCII | 절단 | A§2.2 문법 |
|---|---|---|---|---|---|---|---|
| A | `harness/lib/harness_core/ids.py:114 slugify()` | 정식 슬러그 생성기 | 비영숫자 런 → `-` 1개 | `.lower()` | 제거(하이픈 치환) | 40자 + 단어 경계 우선 | 준수 |
| B | `harness/lib/harness_core/schema.py:203` `normalize_tags()` 인라인 | 태그값 슬러그화 | 압축·strip 없음 | `.lower()` | 보존 | 없음 | 위반 |
| C | `harness/lib/harness_core/schema.py:196-198` `unclassified/` 조기 반환 | 정규화 전무 | 무처리 | 무처리 | 무처리 | 무처리 | 검사 없음 |

측정 절차: `grep -rn "(?i)def\s+\w*(slug|normali[sz]|sanitiz|kebab|munge)\w*\("
harness/` · `grep -rn "(?i)slug" harness/` · `grep -rn "\.lower\(\)|re\.sub\(|
unicodedata|casefold|NFKD" harness/`. `harness/` 밖 사본은 0건입니다.

**B·C 는 이번 범위 밖입니다**(§범위 밖). 원장 완료 기준 3항 어디에도 태그가
없고, 태그 축 교정은 "값 소멸 대 파일명 위생"의 정책 판단(DN 감)을 요구합니다.

### 호출 그래프

```
ids.slugify  ← 프로덕션 직접 호출자 0
  └ ids.filename (ids.py:152)
      └ paths.doc_path (paths.py:90)
          ├ paths.candidate_paths → gate.py:311 (참조 무결성 E07)

```

`slugify` 는 프로덕션에서 오직 `filename()` 을 통해서만 호출됩니다. 이 좁은
목이 이관의 위험을 낮춥니다.

### 러너의 함정 — 종료 코드만으로 판정할 수 없다

`harness/tests/run.py` 는 **수집된 시험이 0건일 때도** `0 passed, 0 failed` 를
출력하고 종료 코드 0 을 반환합니다. 실측(시험 함수가 없는 파일을 인자로 넘김):

```
python3 harness/tests/run.py /tmp/empty_probe_test.py
→ "0 passed, 0 failed" · exit 0
```

따라서 파일명 오타 · 함수 접두 오타 · 잘못된 디렉터리 배치가 전부 "통과"로
보입니다. C2 가 종료 코드에 더해 **통과 건수 하한 N ≥ 4** 를 요구하는 이유입니다.

두 번째 함정: 파이프를 거치면 종료 코드가 소실됩니다 — `run.py ... | tail;
echo $?` 는 `tail` 의 값을 읽습니다. 검증자는 리다이렉트로 받고 직후에 종료
코드를 읽어야 합니다. 이 함정은 이 설계 작업 중 실제로 한 번 밟았습니다.

세 번째 함정: 베어 `assert` 는 `python3 -O` 에서 **전부 소거**되어 전건 통과로
보입니다. TDD 증거 채취와 검증 실행 모두 `-O` 없이 해야 합니다.

### 러너 규약 (신규 시험 파일이 따라야 할 것)

- 발견: 인자 없으면 `run.py` **자신의 디렉터리**만 비재귀 glob(`test_*.py`).
  → `harness/tests/test_textutil.py` 직하 배치 필수.
- 러너는 `sys.path` 를 건드리지 않습니다. 각 파일이 스스로 부트스트랩합니다 —
  기존 11개 파일 전건 동일 관용구:
  `sys.path.insert(0, str(pathlib.Path(__file__).resolve().parents[1] / "lib"))`
- 수집 조건(프로브 실측): **모듈 최상위 · 이름 `test_` 접두 · callable · 인자
  0개.** 클래스 안 메서드는 **미수집**. 인자를 받으면 수집은 되나 `TypeError` 로
  실패 계상. 실행 순서는 `dir(mod)` 기준 **알파벳 순**(정의 순 아님).
- 픽스처 · 파라미터화 · setup/teardown · skip 이 **전부 없습니다.**
- 단언은 베어 `assert` (기존 분포: `assert` 351건 대 `raise AssertionError`
  11건). 후자는 "예외가 나야 한다" 검증에만 씁니다.
- 실패 보고: `=== FAIL <파일명>::<함수명> ===` + 트레이스백 전문, 마지막 줄
  `N passed, M failed`. 종료 코드 0=전건통과 / 1=실패검출 / 2=실행오류.

### 외부 패키지 관련 정정

프롬프트는 "pytest · pip 가 없습니다"라고 했으나 **pip 는 있습니다** —
실측 `python3 -m pip --version` → `pip 25.1.1`. 다만
`/usr/lib/python3.13/EXTERNALLY-MANAGED`(PEP 668)로 시스템 설치가 차단됩니다.
pytest 는 실제로 없습니다. **결론(외부 패키지에 의존하지 않는다)은 그대로
유효**하고 근거 문장만 정정 대상입니다. `run.py` docstring 의 "pip 가 없다"도
같은 정정 대상이나 이번 범위 밖입니다.

## 모듈 관례 — `textutil.py` 가 따라야 할 것

`harness_core/*.py` 18개 파일 헤더 일괄 실측 결과입니다.

1. **모듈 docstring 첫 줄은 정본 주소.** `__init__.py:8-9` 가 규약으로
   명문화합니다 — "주소 없는 모듈은 어느 계약도 구현하지 않는 것이므로 존재
   근거가 없다." → `"""정본: A§2.2 파일명과 슬러그."""` 형태 필수.
2. docstring 2문단 이후는 **"어떤 대안을 왜 배제했는지"**. 기존
   `ids.slugify` docstring(비ASCII 음역 배제 근거)이 그대로 옮겨갈 자산입니다.
3. `from __future__ import annotations` — 17/17 모듈 전건 존재. 필수.
4. 임포트 순서: `__future__` → 표준 라이브러리(알파벳) → 빈 줄 →
   `from . import ...`(상대 임포트, 한 줄 알파벳 순).
5. 제3자 의존은 `yaml` 하나뿐이고 `frontmatter.py` 에만 있습니다. `textutil` 은
   **표준 라이브러리(`re`)만** 씁니다.
6. 타입 힌트 전면 사용, PEP 604 신문법(`str | None`).
7. 상수는 모듈 최상위 대문자 + 바로 위 줄에 정본 주소 주석.
8. 절 구분자 주석 `# ── <제목> ────`(U+2500). 언어는 한국어.

`SLUG_MAX`(40) · `SLUG_MIN_MEANINGFUL`(3)은 `ids.py:29-30` 에서 `textutil.py` 로
옮기고 `ids` 가 재노출합니다(`SLUG_MAX = textutil.SLUG_MAX`). `test_ids.py` 는
이 상수를 직접 참조하지 않으므로(실측) 이동만으로 깨지지 않지만, 외부 참조
여지를 남기기 위해 재노출합니다.

`harness_core/__init__.py` 의 `__all__` 에는 이미 10개 모듈이 누락돼 있어
실질 강제 장치가 아니며, `from harness_core import textutil` 은 `__all__` 과
무관하게 동작합니다(실측). **이번에 `__all__` 을 건드리지 않습니다** — 어느
유닛도 `__init__.py` 를 소유하지 않습니다.

## 설계 결정 — 모호성 닫기

원장의 경계 조건 4종은 그대로 두면 각각 두 가지 이상으로 읽힙니다. 구현자가
해석하게 두지 않고 여기서 닫습니다.

| # | 모호성 | **확정** | 근거 |
|---|---|---|---|
| M1 | "공백 압축"이 공백만인가 | **비영숫자 전체.** ASCII 영숫자가 아닌 문자의 연속(공백·구두점·비ASCII 무관)이 하이픈 1개로 접힌다 | 정본 L217 "ASCII 영숫자 외 전부 하이픈 → 연속 하이픈 압축" |
| M2 | "양끝 절단"이 무엇의 절단인가 | **두 개로 분해.** (a) 양끝 하이픈 strip (b) 40자 길이 절단(단어 경계 우선) | 원장의 "양끝"은 (a)를 가리키나 (b)가 정본 계약의 핵심이고 구현 복잡도 대부분이다 |
| M3 | "빈 입력"의 범위 | `''` · 공백만 · 비영숫자만 · **`None`** 4종 전부 `''` | 아래 |
| M4 | 비ASCII: 보존/음역/제거 | **제거**(하이픈 치환). 음역 없음, 유니코드 정규화(NFC/NFKC) 적용 없음 | 정본 L218 원문. 재론 여지 없음 |
| M5 | 유의미 3자 미만 처리 | **`''` 반환.** 원장 목록에 없으나 **5번째 경계 조건으로 추가** | 아래 |

### M2 — 40자 절단은 3분기이고, 그중 하나는 현재 무시험이다

실측한 분기와 경계값입니다.

| 분기 | 대표 입력 | 실측 출력 | 기존 시험 |
|---|---|---|---|
| 하이픈 없음 → 경계 절단 불가 | `'A'*200` | `'a'*40` (40자) | `test_ids.py:81` 있음 |
| 경계 index ≥ 3 → 경계 채택 | `'x'*39 + ' ' + 'y'*10` | `'x'*39` (39자) | **없음** |
| 경계 index < 3 → 경계 포기, 길이 준수 | `'ab ' + 'c'*60` | `'ab-' + 'c'*37` (40자) | **없음** |

`ids.py:130` 의 `boundary >= SLUG_MIN_MEANINGFUL` 분기는 기존 시험이 **덮지
않습니다.** 이관 시 조용히 깨져도 감지되지 않는 자리이므로 신규 시험이 반드시
덮어야 합니다.

관련해 눈에 띄는 결과 하나를 기록합니다 — `slugify('abcd-' + 'e'*60)` 은
`'abcd'`(4자)를 돌려줍니다. 앞 단어가 짧고 뒤 단어가 길면 슬러그가 앞 단어만
남고 붕괴합니다. **이것은 결함이 아니라 문서화된 규칙의 결과입니다** —
docstring 이 "마지막 하이픈에서 자르되, 그러면 3자 미만이 되는 경우에만 경계를
포기한다(길이가 계약, 경계는 선호다)"라고 적었고 `'abcd'` 는 4 ≥ 3 이라 경계가
채택됩니다. 슬러그는 장식 전용(정본 L219)이므로 짧아지는 것이 계약 위반이
아닙니다. 다만 직관에 반하므로 **시험으로 고정**해 이관 중 우연히 바뀌는 것을
막습니다.

### M3 — `None` 을 계약에 넣는다

현행은 `if not title` 가드로 `None` 을 우연히 통과시키지만 타입 힌트는 `str`
입니다. 시그니처를 `normalize_title(text: str | None) -> str` 로 하고
`None → ''` 를 **계약화**합니다. 근거: `gate.py:255` 가 `fm.get("title", "")` 를
넘기는데, frontmatter 에 `title:` 키만 있고 값이 없으면 PyYAML 이 `None` 을
줍니다. 여기서 `TypeError` 를 던지면 게이트가 E05 대신 크래시합니다.

**비문자열 입력(`int` · `bytes` · `list`)의 계약은 이번에 정하지 않습니다.**
현행이 비일관적임을 기록만 합니다 — `slugify(0)` 은 falsy 가드로 `''` 를
반환하고 `slugify(123)` 은 `AttributeError` 로 죽습니다(실측). 이를 `TypeError`
로 통일하는 것은 **관측 동작 변경**이므로 이관 원칙에 어긋납니다. 신규 시험은
이 영역을 단언하지 않고, docstring 에 "미정의"로 적습니다. 별건 등재 대상입니다.

### M5 — 원장이 빠뜨린 가장 중요한 경계

"유의미 문자 3자 미만이면 슬러그 생략"은 원장의 경계 4종에 없습니다. 그런데
**이 저장소의 한국어 제목은 전부 이 분기를 탑니다.**

```
slugify('하네스 설계 — 축 A 문서 체계')  → ''
slugify('문자열 정규화 함수 단일화')     → ''
slugify('한글 제목입니다')              → ''
```

실측: `land.py` 로 최근 착지한 문서 4건이 전건 ID-only 파일명입니다(이 요청의
원장 자신 포함). 실사용에서 가장 빈번한 분기가 원장 목록에서 빠져 있으므로
5번째 경계 조건으로 추가합니다. 원장 `pass` 가 "시험 4건 **이상**"이므로 추가는
기준과 충돌하지 않습니다.

계수 기준도 못박습니다 — 유의미 문자는 `len(re.sub(r"-", "", s))`, 즉 **하이픈
제외** 후 계수입니다. `'a-b'` → 2 → `''`, `'ab-c'` → 3 → `'ab-c'`.

## 회귀 위험과 봉쇄

**[R-1] `ids.slugify` 이관 — 위험 낮음, 그러나 논증이지 측정이 아니다.**

- **통과 수치**: 종료 코드 0 · `AssertionError` 0건 · `ImportError` 0건.
  기대값은 전부 **이관 전 현행 코드에서 실측해 동결**한 값이다.

> 한계를 명시합니다. `'normalize_title' in src` 는 우회 가능합니다 — 구현자가 그

### C5 — 무회귀 (설계 추가)

- **무엇이 충족인가**: 이관이 기존 동작을 바꾸지 않는다.

## 테스트 시나리오

`harness/tests/test_textutil.py` 는 위 §러너 규약을 따릅니다.

1. **비영숫자 런 압축(M1)** — 공백 · 탭/개행 · 구두점 · 비ASCII · 혼합 5종이
   각각 하이픈 1개로 접힌다. `('multi   space') == 'multi-space'` ·
   `('tab\tsep') == 'tab-sep'` · `('1.2.3 version') == '1-2-3-version'` ·
   `('C++ & Rust') == 'c-rust'` · `('  --Hello,,,   World!!  ') == 'hello-world'`.
2. **양끝 하이픈 절단(M2-a)** — 선행/후행 비영숫자에서 생긴 하이픈이 제거된다.
   `('  --Hello,,,   World!!  ') == 'hello-world'` 이고 결과가 `-` 로 시작·끝나지
   않는다.
3. **40자 절단 — 하이픈 없음 분기(M2-b①)** — `('A'*200) == 'a'*40`, 길이 정확히 40.
4. **40자 절단 — 경계 채택 분기(M2-b②)** — `('x'*39 + ' ' + 'y'*10) == 'x'*39`,
   길이 39. **기존 시험이 덮지 않는 분기.**
5. **40자 절단 — 경계 포기 분기(M2-b③)** — `('ab ' + 'c'*60) == 'ab-' + 'c'*37`,
   길이 40. **기존 시험이 덮지 않는 분기.** 아울러
   `('abcd-' + 'e'*60) == 'abcd'` 로 짧은 앞단어 붕괴를 고정한다.
6. **빈 입력 4종(M3)** — `('') == ''` · `('   ') == ''` · `('\t\n') == ''` ·
   `(None) == ''`. `None` 이 판별점이다 — `" ".join(str(v).split())` 류 구현은
   `'None'` 을 반환해 여기서 걸린다.
7. **비ASCII 제거(M4)** — `('한글 제목입니다') == ''` ·
   `('한글 title 혼합') == 'title'` · `('Café Naive') == 'caf-naive'` ·
   `('emoji 🚀 test') == 'emoji-test'` · `('ＡＢＣ fullwidth') == 'fullwidth'`.
   음역이 일어나지 않음(`'café'` 가 `'cafe'` 가 되지 않음)을 명시적으로 단언한다.
8. **유의미 3자 미만 생략(M5)** — `('ab') == ''` · `('a-b') == ''` ·
   `('!!') == ''` · `('abc') == 'abc'`(경계 통과) · `('ab-c') == 'ab-c'`
   (하이픈 제외 계수 3).
9. **A§2.2 문법 부합** — 위 전 사례의 반환값이 `''` 이거나
   `^[a-z0-9]([a-z0-9-]{0,38}[a-z0-9])?$` 에 부합한다.
10. **멱등성** — 시나리오 1~8의 전 입력에 대해
    `normalize_title(normalize_title(x)) == normalize_title(x)`. 반례 0건.
11. **위임 회귀** — `ids.slugify` 가 위임으로 바뀐 뒤에도 `test_ids.py` 의 슬러그
    시험 3건(`:79` · `:85` · `:89`)이 그대로 성립한다.
12. **이관 등가성** — 고정 프로브 18건에서
    `ids.slugify(p) == textutil.normalize_title(p)`.
13. **전체 회귀** — `python3 harness/tests/run.py` 실패 0건, 통과 235 이상.

시나리오 1~10은 C2 가 계수하는 시험이고(하한 4건을 크게 상회), 11~12는 C4,
13은 C5 가 봅니다.

## 작업 분해

파일 소유권이 서로소입니다. 두 유닛이 같은 파일을 쓰지 않습니다.

| 유닛 | 역할 | 파일 범위 | 코드 산출 |
|---|---|---|---|
| U1 | backend-developer | `harness/lib/harness_core/textutil.py` · `harness/tests/test_textutil.py` | 예 |
| U2 | backend-developer | `harness/lib/harness_core/ids.py` | 예 |

**순서는 U1 → U2 이고 병렬이 아닙니다.** U2 의 임포트 대상이 U1 의 산출이므로,
파일 범위가 서로소여도 동시 실행은 성립하지 않습니다.

**U1** 은 TDD 로 진행합니다 — `test_textutil.py` 를 먼저 쓰고 러너로 **실패를
먼저 확보한 뒤** `textutil.py` 를 구현합니다. 실패를 두 번 확보할 것을
권합니다: ① `textutil.py` 부재 상태(`test_textutil.py::<import>` 임포트 실패)
② docstring 만 있는 빈 모듈 상태(시험 여러 건이 각각 `AttributeError`). ②의
출력이 C3 의 `failing_run_excerpt` 로 더 강한 증거입니다 — 시험이 수집·실행
되었음까지 보이기 때문입니다. 어느 쪽을 골랐는지 `deviation_disclosure` 에
적습니다.

U1 을 "시험 유닛"과 "구현 유닛"으로 쪼개지 않습니다. 쪼개서 병렬로 돌리면 실패
확보와 구현 착수가 겹쳐 C3 의 선행성 증거 자체가 성립하지 않습니다.

**U2** 는 `ids.slugify` 본문을 `return textutil.normalize_title(title)` 로 바꾸고
`SLUG_MAX` · `SLUG_MIN_MEANINGFUL` 을 `textutil` 에서 재노출하는 것이 전부입니다.
U2 는 `harness/tests/test_ids.py` 를 **소유하지 않습니다** — 기존 시험을 고쳐서
통과시키는 경로를 능력 차원에서 막기 위해서입니다. 기존 시험이 깨지면 그것은
회귀이고, 시험이 아니라 구현을 고쳐야 합니다.

어느 유닛도 `schema.py` · `__init__.py` · `paths.py` · `gate.py` · `envelope.py` ·
`test_ids.py` 를 소유하지 않습니다.

## 못 하는 것 — 이 설계의 한계

- **기준선 `main` 과의 diff 를 뜨지 못했습니다.** 이 트리는 git 저장소가
  아닙니다. `main` 은 이름으로만 취급했고, 모든 조사는 현재 작업 트리 실측입니다.
  `main` 과 현 트리가 동일하다는 것은 **확인하지 못했습니다.**
- **"흩어져 있다"의 망라성을 보증하지 않습니다.** grep 검색어(`slug` ·
  `normali[sz]` · `sanitiz` · `.lower()` · `re.sub` · `unicodedata`)에 걸리지
  않는 형태(예: `str.translate`/`maketrans` 테이블, 문자 단위 루프)의 정규화가
  있다면 놓쳤습니다. `str.translate` 는 추가 검색하지 않았습니다.
- **`.claude/` 하위 훅 스크립트 6종과 `harness/tools/remote.sh` 의 본문을 정독하지
  않았습니다.** grep 으로 부재만 확인했고 셸 측 정규화(`tr` · `sed`) 유무는
  미확인입니다.
- **스킬·에이전트 문서에 슬러그 규칙이 산문으로 중복 기술돼 있는지 확인하지
  않았습니다.** 코드 단일화가 문서 중복까지 닫는지는 미검증입니다.
- **퍼즈 결과는 표본 위의 값입니다.** 200,000건 퍼즈에서 `ids.slugify` 의 A§2.2
  문법 위반 0건 · `normalize_tags` 슬러그 위반 96.4%(192,841건)를 얻었으나,
  이는 특정 알파벳 · 길이 0~60 · `random.seed(7)` 조건의 수치이고 전체 유니코드
  평면을 덮지 않습니다. 수학적 증명이 아닙니다.
- **성능·경합을 측정하지 않았습니다.** 순수 함수의 위치 이동이라 성능 회귀
  가능성이 낮다고 **추정**하나 재보지 않았으므로 **미검증 추정**입니다.
- **태그 경로 이스케이프의 실질 위협성은 미판정입니다.** 재현만 했고, 태그 값이
  신뢰 경계 밖에서 들어올 수 있는지는 조사하지 않았습니다. 현재로선 에이전트가
  작성한 frontmatter 가 유일한 입력원으로 **보이나** 확인하지 않았습니다 —
  **미검증 추정**.
- **선행 설계 문서의 본문을 읽지 못했습니다**(§원장·선행 산출 불일치).
- **색인 정합성을 복구하지 않았고 원인도 규명하지 않았습니다.**
- **기준선 안정성을 보증하지 않습니다.** 이 트리는 시험 수가 움직인 이력이
  있습니다.
- **판정하지 않습니다.** 이 문서는 기준을 동결할 뿐이고 충족 여부 판정은 검증
  단계의 책무입니다. 이 문서 안의 어떤 문장도 완료 주장이 아닙니다.

## 원장·선행 산출과의 불일치 (3건)

### 불일치 1 — 선행 설계 문서가 색인에는 있고 디스크에는 없다

이 요청의 designing 단계는 이번이 처음이 아닙니다.
`2026-07-29T04:21:43Z` 에 `DS-20260729T042143Z-8dee6d1f` 가 착지한 기록이 있습니다.

- 감사 스트림 `docs/audit/public/2026/07/AU-20260729T042143Z-35678714-agent-events.jsonl`
  2행 `doc.landed`, `req` 가 이 요청과 일치
- 파생 색인 `derived/index/docs.jsonl` 2행 + 태그 색인 4종에 등재
  (제목은 이 요청의 설계 기준 동결 문서이고 기준 16항)
- **실물**: `stat docs/design/public/2026/07/DS-20260729T042143Z-8dee6d1f.md`
  → `No such file or directory (os error 2)`

색인과 감사가 존재를 주장하는 문서가 파일 계층에 없습니다. 선행 `/tmp/design.json`
의 `criteria_ref` 가 이 ID 를 가리키므로 **그대로 두면 후속 게이트가 읽을 수 없는
기준을 참조**합니다. 디렉터리 mtime 은 `13:35`(KST)로 이 세션 개시(`13:38`)
직전입니다.

이 제1판은 새로 착지한 문서를 `criteria_ref` 로 씁니다. 동결된 판을 수정하는
것이 아니라 **읽을 수 없는 참조를 읽을 수 있는 참조로 대체**하는 것입니다.
색인 정합성 복구는 별건 등재 대상입니다.

### 불일치 2 — 원장 기준 1의 `how` 가 실행 불가형이다

§C1 참조. `PYTHONPATH` 부재로 구현이 끝나도 실패합니다. 실행 가능형으로
보정했고 `what` · `pass` 는 원장 그대로입니다.

### 불일치 3 — 선행 산출의 기준선 수치가 현재 트리와 어긋난다

선행 `/tmp/design.json` 은 전체 스위트 기준선을 `227 passed` 로 동결하고 회귀
기준을 `passed >= 231` 로 잡았습니다. **현재 실측은 `231 passed, 0 failed`**
(3회 반복 동일, 파일별 합계 교차검산)입니다. 즉 선행 기준의 `>= 231` 은 **신규
시험을 한 건도 추가하지 않아도 이미 통과**하며 회귀 기준으로서 판별력을
잃었습니다. 라이브러리 파일 해시는 선행 기록과 전건 일치하므로
(`ids.py` · `schema.py` · `run.py` · `test_ids.py` 4건 대조) 변한 것은 라이브러리가
아니라 시험 쪽입니다. 이 판은 기준선을 231 로 다시 재고 하한을 235 로 잡습니다.
