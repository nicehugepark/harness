## 요약

`ids.slugify()` 의 슬러그 정규화 로직을 `harness/lib/harness_core/textutil.py` 의
`normalize_title()` 로 **이관**하고, `ids.slugify` 를 얇은 위임으로 남기며, 경계
조건을 시험으로 고정하는 설계입니다. 검증 기준 7항을 **제2판**으로 동결합니다.

제1판(`DS-20260729T045701Z-b08e0070`)은 적대 리뷰에서 must-fix 3건으로
불통과했습니다. 제1판은 동결된 판이므로 **수정하지 않았고**, 이 문서가 새 판입니다.
제1판의 조사 결과(§흩어짐의 형태 · §모듈 관례 · §설계 결정 M1~M5 · §범위 밖 8항)는
리뷰에서 반증되지 않았으므로 계승하고, **반증된 것과 우회가 실증된 기준만
교체**했습니다.

## 정정 — 제1판의 거짓 사실 주장 1건

제1판은 "이 작업 트리는 git 저장소가 아니다(`.git` 부재)"라고 적고, 그것을 근거로
기준선 `main` 과의 대조를 건너뛰었습니다. **이 주장은 현재 거짓입니다.**

| 항목 | 제2판 실측 (2026-07-29T14:38 KST 이후) |
|---|---|
| `git rev-parse --git-dir` | `.git` · 종료 코드 0 |
| `git rev-parse --abbrev-ref HEAD` | `main` |
| `git diff main --name-only -- harness/` | **0행** — 코드 축이 `main` 과 동일 |
| `git ls-files --others --exclude-standard -- harness/` | 0행 |

이 정정이 must-fix 2 의 직접 해소 수단입니다. 기준선을 문서에 상수로 얼리는 대신
**검증 시점에 ref `main` 에서 다시 재는** 형이 가능해졌습니다.

리뷰어는 제1판 측정 시점(13:52 이전)에는 참이었을 수 있다고 적었습니다. 저는 그
시점의 상태를 **확인하지 못했습니다** — reflog 에 `13:52:16 reset: moving to
origin/main` 항목이 있다는 리뷰어 기록을 재확인하지 않았습니다.

## 기준선 — 절대 상수를 쓰지 않는 이유

세 시점의 전체 스위트 실측입니다.

| 시점 | 측정 주체 | 값 |
|---|---|---|
| 제1판 동결 (13:57) | architect | `231 passed, 0 failed` |
| 적대 리뷰 (14:2x) | qa | `232 passed, 0 failed` |
| **제2판 동결** | architect (3회 반복 동일) | **`232 passed, 0 failed`** |

`main` 도 움직였습니다 — 리뷰 시점 `dc56cc3…`, 제2판 동결 시점 `48b44ff…`
(ref 이름으로만 다루므로 본문에 해시를 상수로 쓰지 않습니다).

값이 두 번 움직였다는 사실 자체가 절대 상수 하한이 회귀 감지기로 부적합함을
보입니다. 상수 하한은 두 방향으로 무너집니다.

1. **위로 무너짐** — 트리가 자라면 하한이 저절로 충족되어 판별력이 0 이 됩니다.
   제1판이 인용한 선행 산출의 `>= 231` 이 이미 그렇게 됐습니다.
2. **옆으로 무너짐** — 계수는 '기존 1건 삭제 + 신규 4건 추가'와 '신규 4건 추가'를
   **구별하지 못합니다.** 리뷰어가 실증했고 저도 재현했습니다.

그래서 C6 은 계수가 아니라 **시험 신원(파일::함수) 집합의 포함관계**로 판정하고,
기준선을 검증 시점에 `git archive main` 으로 다시 뽑습니다. 트리가 또 움직여도
"기준선에 있던 시험이 산출 트리에 전건 남아 있는가"라는 질문의 답은 흔들리지
않습니다.

계수를 완전히 버리지는 않았습니다 — 러너 통과 수와 수집 신원 수의 **교차검산**에
씁니다. 두 값이 어긋나면 수집 누락이나 중복이 있는 것입니다.

## 우회 실증 — 새 기준이 실제로 막는지 재봤습니다

리뷰어가 쓴 우회 수법을 그대로 재현하고, 새 기준 7항을 **원문 그대로** 실행해
종료 코드를 관측했습니다. 세 산출을 만들었습니다.

- **(가) 우회 산출** — 리뷰 `findings[0].evidence` 원문 재현: `ids.py` 의 `slugify`
  본문을 `_legacy_slug` 로 이름만 바꿔 온존 + `slugify` 는 docstring 과
  `# normalize_title` 주석만 달고 `_legacy_slug` 호출 + `textutil.py` 에 독립된
  2번째 사본. 여기에 리뷰 `findings[1]` 의 회귀 은폐(기존 시험
  `test_batch.py::test_batch_commit_lands_staged_documents` 삭제 + 신규 4건)와
  `findings[4]` 의 경계 미커버 시험 4건을 합쳤습니다.
- **(나) 준수 산출** — 로직을 통째로 `textutil` 로 옮기고 `ids.slugify` 를 위임으로
  남긴 것 + 계약된 13개 이름의 시험 파일.
- **(다) 현 트리** — 미구현 상태.

(가)·(나)는 `git init` 한 `/tmp` 샌드박스로 만들어 `main` 을 현행 기준선으로 두고
`cwd` 를 저장소 루트로 하여 기준을 원문 실행했습니다. 셋 다 착지시키지 않았습니다.

### 대조 — 제1판 기준을 같은 우회 산출에 실행한 결과

리뷰어의 주장을 제 손으로 재현했습니다.

| 제1판 기준 | (가) 우회 산출에서의 결과 |
|---|---|
| C4 원문 | **종료 코드 0 — 통과** (구조 검사 2건 + 하드코딩 기대값 전건 통과) |
| C5 원문 | **종료 코드 0 · `235 passed, 0 failed` — `passed >= 235` 충족** |
| C3 의 `'test_textutil' in x and 'failed' in x` | 위조 발췌 `"=== harness/tests/test_textutil.py ===\n10 passed, 0 failed"` 에 대해 **`True`** |

동시에 런타임 센티널 프로브(`textutil.normalize_title` 을 람다로 치환 후
`ids.slugify('Hello World')` 호출)는 `'hello-world'` 를 돌려주어, 이 산출이
`textutil` 을 **전혀 경유하지 않음**을 보였습니다.

### must-fix 별 닫은 방식과 재현 명령

**must-fix 1 (C4 가 사본 산출을 막지 못함) → 런타임 센티널로 닫음.**
문자열 검사는 원리상 우회 가능합니다(주석·이름 바꾸기). 실행 중 실제로 어느
함수가 값을 만드는지는 문자열로 알 수 없으므로, `textutil.normalize_title` 을
센티널로 치환하고 `ids.slugify` 의 반환값이 따라 바뀌는지를 직접 잽니다. 이것이
통과하려면 `ids` 가 **늦은 바인딩**(`textutil.normalize_title(...)` 형태 호출)으로
호출하는 수밖에 없고, 그 순간 로직의 소재지는 하나가 됩니다. 부수적으로
`from .textutil import normalize_title` 형태의 이른 바인딩도 배제되는데, 이는
§모듈 관례 4항(`from . import ...` 상대 임포트)과 일치합니다.

역방향(로직을 `ids` 에 두고 `textutil` 이 감싸는 형)은 센티널을 통과하므로
`textutil` 소스의 `ids` 참조 0건 검사를 함께 둡니다.

**must-fix 2 (절대 상수 하한) → 기준선 재측정 + 신원 집합으로 닫음.** 위 §기준선.

**must-fix 3 (`'failed'` 부분 문자열) → 실패 마커 + 실패 계수로 닫음.**
러너 마지막 줄은 언제나 `N passed, M failed` 형식이므로 `'failed'` 는 정보를
담지 않습니다. 대신 러너가 **실패했을 때만** 찍는 `=== FAIL <라벨> ===` 마커를
정규식으로 찾고, 집계 줄을 파싱해 실패 수 `M >= 1` 인 줄이 있는지 봅니다.
마커의 라벨이 `test_textutil` 계열인지도 확인합니다.

## 조사 결과 계승 — "흩어져 있다"의 실제 형태

제1판 조사를 계승합니다(리뷰에서 반증되지 않았고, 리뷰어도 `harness/` 밖 슬러그
정규화 `def` 0건을 재확인했습니다). 문서 슬러그를 만드는 **정식 함수는 1개**이고,
흩어진 것은 함수가 아니라 "슬러그화해야 하는데 하지 않는 자리"입니다.

| # | 위치 | 성격 | A§2.2 문법 |
|---|---|---|---|
| A | `harness/lib/harness_core/ids.py` `slugify()` | 정식 슬러그 생성기 | 준수 |
| B | `harness/lib/harness_core/schema.py` `normalize_tags()` 인라인 | 태그값 슬러그화 · 압축·절단 없음 | 위반 |
| C | `harness/lib/harness_core/schema.py` `unclassified/` 조기 반환 | 정규화 전무 | 검사 없음 |

**B·C 는 이번 범위 밖입니다.** 원장 완료 기준 3항 어디에도 태그가 없고, 태그 축
교정은 "값 소멸 대 파일명 위생"의 정책 판단을 요구합니다.

`slugify` 는 프로덕션에서 오직 `ids.filename()` 을 통해서만 호출됩니다
(`ids.filename` → `paths.doc_path` → `gate.land` · `envelope._new_file`).
이 좁은 목이 이관의 위험을 낮춥니다. **`ids.slugify` 를 삭제하지 않습니다** —
삭제하면 4계층이 동시에 흔들립니다.

## 설계 결정 — 모호성 닫기 (제1판 계승)

| # | 모호성 | 확정 | 근거 |
|---|---|---|---|
| M1 | "공백 압축"의 범위 | **비영숫자 전체.** ASCII 영숫자가 아닌 문자의 연속이 하이픈 1개로 접힌다 | 정본 A§2.2 |
| M2 | "양끝 절단"의 대상 | **분해.** (a) 양끝 하이픈 strip (b) 40자 길이 절단(단어 경계 우선, 3분기) | 원장의 "양끝"은 (a), 정본 계약의 핵심은 (b) |
| M3 | "빈 입력"의 범위 | `''` · 공백만 · 비영숫자만 · **`None`** 4종 전부 `''` | `gate` 가 `fm.get("title", "")` 를 넘기는데 PyYAML 이 값 없는 `title:` 에 `None` 을 준다 |
| M4 | 비ASCII | **제거**(하이픈 치환). 음역 없음, NFC/NFKC 적용 없음 | 정본 — 플랫폼별 유니코드 정규화 차이 차단 |
| M5 | 유의미 3자 미만 | **`''` 반환.** 원장 목록에 없으나 5번째 경계로 추가 | 이 저장소의 한국어 제목이 전부 이 분기를 탄다 |

M5 의 계수 기준을 못박습니다 — 유의미 문자는 **하이픈 제외** 후 계수입니다.
`'a-b'` → 2 → `''`, `'ab-c'` → 3 → `'ab-c'`. 리뷰어가 이 축이 제1판 기준에
고정돼 있지 않다고 지적했고, 제2판 C5 오라클 표가 두 값을 모두 고정합니다.

M2 의 40자 절단 3분기 중 **경계 채택**(`'x'*39 + ' ' + 'y'*10` → `'x'*39`)과
**경계 포기**(`'ab ' + 'c'*60` → `'ab-' + 'c'*37`) 두 분기는 기존 `test_ids.py` 가
덮지 않습니다. 이관 중 조용히 깨져도 감지되지 않는 자리이므로 신규 시험과
C5 오라클이 함께 덮습니다.

`slugify('abcd-' + 'e'*60)` → `'abcd'`(4자)는 결함이 아니라 문서화된 규칙의
결과입니다(4 >= 3 이라 경계가 채택됨). 직관에 반하므로 시험과 오라클로 고정해
이관 중 우연히 바뀌는 것을 막습니다.

**비문자열 입력(`int` · `bytes` · `list`)의 계약은 이번에 정하지 않습니다.**
현행이 비일관적임을 기록만 합니다 — `slugify(0)` 은 falsy 가드로 `''` 를
반환하고 `slugify(123)` 은 `AttributeError` 로 죽습니다. 통일은 **관측 동작
변경**이라 이관 원칙에 어긋납니다. 신규 시험은 이 영역을 단언하지 않고
docstring 에 "미정의"로 적습니다. 별건 등재 대상입니다.

## 러너 규약과 함정 (제1판 계승 · 리뷰에서 재현됨)

- **발견**: 인자 없으면 `run.py` **자신의 디렉터리**만 비재귀 glob(`test_*.py`).
  → `harness/tests/test_textutil.py` 직하 배치 필수.
- **부트스트랩**: 러너는 `sys.path` 를 건드리지 않습니다. 각 파일이 스스로
  `sys.path.insert(0, str(pathlib.Path(__file__).resolve().parents[1] / "lib"))`.
- **수집 조건**: 모듈 최상위 · `test_` 접두 · callable · 인자 0개. 클래스 안
  메서드는 미수집. 실행 순서는 `dir(mod)` 기준 알파벳 순.
- 픽스처 · 파라미터화 · setup/teardown · skip 이 전부 없습니다.
- **함정 1 — 수집 0건도 통과로 보입니다.** `0 passed, 0 failed` + 종료 코드 0.
  파일명 오타 · 함수 접두 오타 · 잘못된 배치가 전부 "통과"입니다. C2·C6 이
  종료 코드에 더해 **수집 신원과 통과 수의 교차검산**을 하는 이유입니다.
- **함정 2 — 파이프를 거치면 종료 코드가 소실됩니다.** 제2판의 모든 기준은
  파이프를 쓰지 않고 `subprocess` 의 반환값을 직접 읽습니다.
- **함정 3 — 베어 `assert` 는 `python3 -O` 에서 전부 소거됩니다.** TDD 증거
  채취와 검증 실행 모두 `-O` 없이 합니다.

## 모듈 관례 — `textutil.py` 가 따라야 할 것 (제1판 계승)

`harness_core/*.py` 헤더 일괄 실측 결과입니다. 리뷰어는 이 항목을 재측정하지
않았다고 밝혔으므로 **독립 재확인은 없습니다.**

1. 모듈 docstring 첫 줄은 정본 주소 — `"""정본: A§2.2 파일명과 슬러그."""`.
2. docstring 2문단 이후는 "어떤 대안을 왜 배제했는지". 기존 `ids.slugify`
   docstring(비ASCII 음역 배제 근거)이 그대로 옮겨갈 자산입니다.
3. `from __future__ import annotations` — 필수.
4. 임포트 순서: `__future__` → 표준 라이브러리(알파벳) → 빈 줄 →
   `from . import ...`(상대 임포트).
5. 제3자 의존 금지. `textutil` 은 표준 라이브러리(`re`)만 씁니다.
6. 타입 힌트 전면 사용, PEP 604 신문법(`str | None`).
7. 상수는 모듈 최상위 대문자 + 바로 위 줄에 정본 주소 주석.
8. 절 구분자 주석 `# ── <제목> ────`(U+2500). 언어는 한국어.

`SLUG_MAX`(40) · `SLUG_MIN_MEANINGFUL`(3)은 `ids.py` 에서 `textutil.py` 로 옮기고
`ids` 가 재노출합니다(`SLUG_MAX = textutil.SLUG_MAX`). `test_ids.py` 는 이 상수를
직접 참조하지 않으므로(실측 · 리뷰어 재확인) 이동만으로 깨지지 않지만, 외부 참조
여지를 남기기 위해 재노출합니다. **이 상수 이전은 U1·U2 에 걸친 계약이므로
아래 §작업 분해의 산출 계약란에 명시했습니다** — 제1판은 별도 절 산문에만 두어
분해 표에서 누락됐습니다(리뷰 note).

`harness_core/__init__.py` 의 `__all__` 은 **건드리지 않습니다** — 어느 유닛도
`__init__.py` 를 소유하지 않습니다. `from harness_core import textutil` 은
`__all__` 과 무관하게 동작합니다(실측).

## 검증 기준

판 번호 **제2판**. 이 판은 산출물을 보기 전에 동결되며 어떤 방향으로도 수정하지
않습니다. 엄격화가 필요하면 제3판을 새로 냅니다. 제1판은 동결된 채 남으며 이
문서가 제1판을 수정하지 않습니다.

기준 3항만으로는 아무것도 모으지 않고 새 파일만 추가해도 통과하며, 이것은
제1판이 이미 짚은 논거입니다. 제2판은 같은 논거가 **제1판 C4 자신에게도
성립했다**는 리뷰 지적을 받아 그 자리를 런타임 검사로 교체했습니다.

  회귀 가능성이 낮다고 **추정**하나 재보지 않았으므로 **미검증 추정**입니다.
- **`origin/main` 과 다른 머신 트리와의 차이를 확인하지 않았습니다.** 로컬 ref
  `main` 만 봤습니다.
- **판정하지 않습니다.** 이 문서는 기준을 동결할 뿐이고 충족 여부 판정은 검증
  단계의 책무입니다. 이 문서 안의 어떤 문장도 완료 주장이 아닙니다.

## 원장과의 불일치 (1건)

**원장 완료 기준 1 의 `how` 가 실행 불가형입니다.** `python3 -c 'from
harness_core import textutil; textutil.normalize_title'` 는 `PYTHONPATH` 가 없어
구현이 끝나도 `ModuleNotFoundError` 로 실패합니다. 현행 `ids` 로 재현
확인했습니다 — `PYTHONPATH=harness/lib` 를 주면 종료 코드 0. 검증자가 이를
"미구현"으로 오판할 수 있으므로 C1 에서 실행 가능형으로 보정했습니다. 원장의
`what` 의도(임포트 성공 · 예외 0건)와 `pass` 는 유지했습니다.

원장 완료 기준 2·3 은 C2·C3 이 대응하되 **엄격화**했습니다. 원장 기준 2 의
`pass`("시험 4건 이상")는 어떤 경계가 덮였는지 보지 않고, 원장 기준 3 의
`pass`("`failing_run_excerpt` 에 실패 출력 포함")는 제1판의 구현형이 실패를
판정하지 못했습니다. 원장 `pass` 가 "4건 **이상**"이므로 13건 계약은 원장과
충돌하지 않습니다.
