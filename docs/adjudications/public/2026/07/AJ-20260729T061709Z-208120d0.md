## 요약

요청 `RQ-20260729T040046Z-0f28a578`(문자열 정규화 함수 단일화)의 설계 리뷰 반려
상한 `Ed=2` 가 소진되었습니다. 설계 2판이 모두 적대 리뷰에서 불통과했고, 3회차
반려는 전이 가드가 거부했습니다(실측: `designing → designing: 설계 리뷰 반려
상한 Ed=2 소진`).

규정상 상한 소진은 **요구가 모호하다는 판정**이므로 재작업하지 않고 상신합니다.
사람의 응답이 착지해야 재개합니다 — 메시지는 승인이 아닙니다.

## 미해결 must-fix 2건

### ① 시험 자산의 실질성을 기계로 고정할 수 없다

제2판 C2 는 시험 함수의 **이름 13종**을 계약합니다. 그런데 그 13개 본문을 전부
`assert True` 로 두고 정상 구현을 붙이면 기준 7항이 **전건 통과**합니다.
TDD 실패 증거(C3)까지 위조 없이 진짜로 확보됩니다 — 시험 파일이 모듈 최상위에서
구현을 임포트하므로 구현 부재 시 실제로 실패하기 때문입니다.

원장 완료 기준 2의 `what` 은 "경계 조건이 시험으로 고정된다"이고 `pass` 는
"실패 0건 · 시험 4건 이상"입니다. **계수와 실패 0건만으로는 판별력 있는 시험과
공허한 시험을 구별할 수 없습니다.** 이것은 설계 결함이 아니라 원장이 준 완료
기준의 표현력 한계입니다.

닫으려면 변이 시험(구현을 의도적으로 망가뜨렸을 때 시험이 실패하는지 측정)을
완료 기준에 넣어야 하는데, 설계자는 그것이 구현 형태를 과도하게 구속한다는
이유로 기준에서 뺐습니다. 어느 쪽을 택할지는 **요구의 문제**이지 설계의 문제가
아닙니다.

### ② 공유 작업 트리에서 파일 범위 검사가 올바른 산출을 반려한다

제2판 C7 은 `git diff main` 으로 변경 파일이 허용 3파일 안인지 봅니다. 그런데 이
트리는 여러 작업이 동시에 `harness/` 를 고치는 공유 트리입니다. 무관한 미커밋
변경이 하나만 있어도 완전히 올바른 산출이 불통과합니다(리뷰어 실측: 무관한 변경
2건 추가 시 C7 종료 코드 1, 같은 트리에서 C6 은 0).

실측 근거 — 약 1시간 동안 `harness/` 경로가 3회 변동했습니다. 설계는 "`harness/`
변동 0행"을 안정적 성질로 전제했으나 실측상 커밋 직후에만 잠깐 참인 과도
상태입니다.

## 결정을 요청하는 사항

아래 중 하나를 골라 주십시오. 고른 항목과 사유를 이 문서에 응답으로 착지시켜
주시면 재개합니다.

**A. 완료 기준을 강화한다.** 원장 완료 기준 2에 변이 시험을 명시적으로 추가하고,
그로 인한 구현 형태 구속을 수용합니다. 제3판을 낼 근거가 생깁니다.

**B. 판정 범위를 나눈다.** 시험의 실질성은 기계 판정 대상에서 제외하고 검증
단계의 코드 리뷰로 처분한다고 명시합니다. 아울러 C7 을 "작업 트리 전체 대 main"
이 아니라 "이 유닛이 실제로 건드린 파일"만 보도록 좁힙니다.

**C. 알려진 한계로 수용하고 제2판 그대로 진행한다.** 구멍 2건을 문서에 기록한
채 building 으로 넘어갑니다. 이 선택은 "완주 확인"이라는 원장 `why` 를
우선하고 기준의 엄밀성을 후순위로 둡니다.

**D. 요청을 보류하거나 폐기한다.**

## 도구 한계 — 재개 시 걸릴 것

현재 사용 가능한 도구(`advance.py`)는 원장의 `state` 와 계수기만 씁니다.
`refs.adjudications` 슬롯을 **쓰지 못합니다.** 그런데 `hold → queued` 재개 전이의
가드(`g_human_answer`)는 `refs.adjudications` 와 `adjudication_answered` 를 둘 다
요구합니다. 따라서 이 문서에 응답이 착지해도 **원장의 `refs` 를 갱신하는 별도
조작 없이는 재개 전이가 거부됩니다.** 이것은 이 요청과 별개의 도구 결손이며
여기서 고치지 않고 표면화만 합니다.
