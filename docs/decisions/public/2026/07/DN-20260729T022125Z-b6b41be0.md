## 요약

**확정** — 저장소 공개 범위·에이전트 표시명·배치 표면의 버전관리 지위 3건을 확정합니다.

## 결정

### 1. 원격 저장소를 public 으로 한다 (S§2-2 개정)

확정 제약 2항은 개인 GitHub 계정의 **private** 저장소를 원격으로 쓴다고 정했습니다.
의사결정권자가 이를 **public** 으로 바꾸고 GitHub Pages 로 대시보드를 서비스하기로
확정했습니다.

바뀌는 위험의 성질을 명시합니다. private 원격에서 오분류의 피해는 "계정 소유자만
봄"이었지만 public 에서는 즉시 공개이고 히스토리에서 제거되지 않습니다(비가역).
private 판정의 내용 축(하네스 밖 프로젝트 원문·실명·실주소)은 설계가 장치 불가로
명시한 자리이고, 자격증명 패턴 검출 E12 는 그 축을 커버하지 않습니다.

수용에 동반하는 장치:
- 커밋 전 정제 스캔을 게이트로 둔다 — 추적 대상 전문 + **파일 경로 자체**를 스캔한다.
- 스캔은 고정 스크립트로만 실행한다. 대소문자 무시 옵션이 붙으면 판정이 무효가 된다.
- GitHub Pages 의 서비스 대상은 문서 트리가 아니라 빌드 산출물로 좁힌다. 같은
  저장소에서 문서 트리를 그대로 서비스하면 브라우징 표면이 한 겹 더 열린다.

### 2. 에이전트 표시명은 선행 운영 명명 체계를 승계한다

선행 운영의 역할↔이름 매핑을 실측해 9역할을 직접 승계하고, 대응 역할이 없던
5역할은 같은 작품군에서 차용했습니다. 표시명은 이름 레지스트리가 정본이고 문서의
`author`·`participants` 필드에 정상 노출됩니다.

| 역할 | 표시명 | 지위 |
|---|---|---|
| lead · pm · architect · qa | 타치코마 · 아라마키 · 쿠사나기 · 토구사 | 승계 |
| security-engineer · devops-engineer · data-engineer | 보마 · 파즈 · 이시카와 | 승계 |
| backend-developer · frontend-developer | 아즈마 · 프로토 | 승계 |
| staff-engineer | 바토 | 차용 — 전 구간 횡단·난제 직접 해결 |
| designer | 사이토 | 차용 — 시각 축 |
| caveman · freshman | 로지코마 · 우치코마 | 차용 — 전신 기종 / 후속 기종(신참) |
| document-specialist | 쿠제 | 차용 — 언어·서술 축 |

정제 스캔 목록에서 표시명 패턴을 **삭제**했습니다. 억제가 아니라 삭제인 근거:
실제 적용량이 0이 된 규칙은 남기지 않습니다 — 남기면 다음 사람이 그 규칙을
살아 있는 금지로 읽습니다.

### 3. `.claude/` 는 버전관리 밖이다

배치 표면입니다. 소스는 `harness/assets/` 이고 여기 놓이는 것은 배치본(파생)입니다.

근거 셋:
- 배치본을 커밋하면 원본과 두 벌이 되어 사본 발산이 시작됩니다.
- 백업 범위 `project_claude_config` 가 보존을 책임집니다.
- 클론 후 설치기를 돌려야 자산이 놓이는 것이 설계된 동작입니다.

## 장치

| 결정 | 장치 | 집행 지점 |
|---|---|---|
| 1 | 정제 스캔 고정 스크립트 — 종료 코드 1이면 커밋하지 않는다 | `harness/tools/sanitize.py` |
| 2 | 이름 레지스트리 유일성 불변식 + 착지 게이트의 표시명 대조 | `harness_core/registry.py` · 착지 게이트 |
| 3 | `.gitignore` 6행 | 저장소 정본 |

## 근거

- 1: 공개 전환은 오분류 피해의 가역성을 바꾼다. 장치를 늘리지 않으면 규율만 남는다.
- 2: 표시명 부재는 이름 해석을 통째로 죽인다. 임시값(역할 키)을 방치하면 문서마다
  누적되고, 나중에 바꿔도 과거 문서는 소급 수정하지 않는 것이 규약이라 영구히 남는다.
- 3: 같은 자산의 사본이 두 곳에 있으면 어느 쪽이 정본인지 판정할 수 없게 된다.

## 대안·기각

- **1 기각안**: private 유지. 대시보드를 GitHub Pages 로 서비스하려면 public 이
  필요하다는 의사결정권자의 목적과 충돌한다.
- **2 기각안**: 역할 키를 표시명으로. 정제 스캔은 0이 되지만 설계가 금지한
  "역할 키 단독 표기"와 구별되지 않는다.
- **3 기각안**: 배치본도 커밋. 사본 발산을 감시하는 장치가 또 필요해진다.

## 결과·경계

- 이 결정은 **원격 생성·push 를 승인하지 않는다.** 로컬 커밋까지만 유효하다.
  실제 공개는 공개될 파일 전수 목록을 확인받은 뒤에 한다.
- 결정 1은 확정 제약 문면의 개정이므로 스펙 문서에 반영이 필요하다. 그 반영은
  후속 요청이다.

## 규율

- [R1] 정제 스캔 검출이 0이 아닌 상태로 커밋하지 않는다.
  [장치 — 스캔 스크립트의 종료 코드가 1이고, 커밋 절차가 그것을 게이트로 읽는다. 스캔 범위는 추적 대상 전문 + 파일 경로이며 대소문자를 구분한다 | 장치 불가 — 패턴에 걸리지 않는 산문형 유출은 원리적으로 불완전하다. 완화: 공개 전 전수 목록 확인]
- [R2] 표시명 변경 시 과거 문서를 소급 수정하지 않는다.
  [장치 — 레지스트리의 history 가 시점 매핑을 제공하고, 문서 트리의 정본은 불변이다 | 장치 불가 — 해당 없음]
