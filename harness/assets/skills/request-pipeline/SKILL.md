# request-pipeline

**요청 1건 = 세션 1개**입니다. 이 세션이 실행 컨테이너이자 감사 경계입니다.
이 안에서 단계별로 에이전트를 스폰하고, 각 산출을 게이트에 통과시킨 뒤에만
다음 단계로 갑니다.

## 이 세션은 **한 턴**입니다 — 가장 중요한 제약

이 세션은 비대화 1턴으로 돕니다. **턴이 끝나면 세션이 죽습니다.**

그래서 **어떤 작업도 백그라운드로 돌리고 기다리면 안 됩니다.** "백그라운드에서
실행 중이며 완료되면 이어가겠습니다"라고 적는 순간 세션이 종료되고 요청은
그 상태에서 영구히 멈춥니다(실사고 2026-07-29T05:05 — 설계 산출까지 하고 멈췄습니다).

- 하위 에이전트는 **Task 도구로 동기 호출**합니다. Task 는 결과를 돌려주고,
  그때까지 이 턴은 끝나지 않습니다.
- `run_in_background`·`nohup`·`&` 를 쓰지 않습니다.
- 한 턴 안에서 designing → building → verifying → merging 을 **끝까지** 갑니다.
- 끝까지 못 가면 마지막에 반드시 `advance.py` 로 `hold` 로 떨어뜨립니다 —
  멈춘 채 방치되는 것이 가장 나쁩니다.

## 상태는 이 도구로만 씁니다

게이트를 통과할 때마다 원장에 전이를 **적용**해야 합니다. 적용하지 않으면
여러분이 옳게 진행해도 원장은 그대로이고, 스케줄러는 아무 일도 없었다고 봅니다.

```
python3 harness/tools/advance.py --ledger <원장경로> --to building \
    --payload /tmp/payload.json
```

`--lease` 는 `HARNESS_SESSION` 환경변수에서 자동으로 옵니다. lease 가 맞지
않으면 거부됩니다 — 그것이 이중 세션 차단입니다.

## 절대 규칙

1. **첫 행동은 `HARNESS_REQ` 가 가리키는 원장 문서의 전문을 읽는 것**입니다.
   프롬프트에 요약이 실려 있어도 원장이 정본이고, 어긋나면 원장을 따르고
   불일치를 보고합니다.
2. **판정은 여러분이 하지 않습니다.** "통과했습니다"라고 적는 것은 판정이
   아닙니다. `harness/tools/gatecheck.py` 의 **종료 코드**가 판정입니다.
   게이트를 통과하지 못하면 다음 단계로 가지 않습니다.
3. **완료 기준을 프롬프트에 재기술하지 않습니다.** 하위 에이전트에게는 원장
   경로를 넘기고 직접 읽게 합니다. 커밋 해시 리터럴을 넘기지 않습니다.
4. 문서 착지는 `harness/tools/land.py` 로만 합니다. `docs/` 직접 쓰기는
   차단됩니다.

## 단계

### 1. designing — 설계와 기준 동결

`architect` 를 스폰합니다(`staff-engineer` 를 함께 참여시킵니다). 산출은
검증 기준(항목마다 **무엇이 충족인가 / 무엇으로 확인하는가 / 통과 수치** 3요소),
테스트 시나리오, 작업 분해(파일 소유권이 **서로소**)입니다.

그 다음 `qa` 를 **적대 리뷰**로 스폰합니다. 리뷰 산출에는 무엇을 봤는지와
**무엇을 보지 않았는지**가 둘 다 있어야 합니다 — 후자가 비면 게이트가 막습니다.

```
python3 harness/tools/gatecheck.py review --file /tmp/review.json
```

불통과면 설계를 고쳐 다시 리뷰합니다. 반려가 상한(정책값)에 닿으면 재작업하지
않고 **사람에게 상신**합니다 — 요구가 모호하다는 판정이기 때문입니다.

### 2. building — 병렬 구현

작업 분해의 유닛마다 담당 역할을 **동시에** 스폰합니다. 파일 소유권이 서로소라
편집은 병렬로 안전합니다. 각 워커에게는 원장 경로·유닛 ID·파일 범위·기준선
ref 만 넘깁니다.

워커는 **실패하는 테스트를 먼저** 만들고 그 실패 출력을 증거로 남긴 뒤 구현합니다.

```
python3 harness/tools/gatecheck.py evidence --file /tmp/report.json \
    --output-kind <원장의 output_kind> --produces-code <true|false>
```

### 3. verifying — 3렌즈

`caveman` 과 `freshman` 을 **동시에** 스폰합니다. 두 렌즈에게는 **검증 기준을
주지 않습니다** — 기준이 입력이면 무전제 관점이 오염됩니다. 두 렌즈는 판정하지
않고 관찰·기대 차이·앵커만 냅니다.

그 다음 `qa` 를 스폰해 판정을 받습니다. qa 는 기준 항목 **전건**과 수신 의견
**전건**을 처분해야 합니다.

```
python3 harness/tools/gatecheck.py verify --file /tmp/verdict.json \
    --criteria /tmp/criteria.json --opinions /tmp/opinions.json
```

`staff-engineer` 는 이 단계에 **참여하지 않습니다** — 전 구간에 손댄 자가
판정하면 자기 검증입니다.

### 4. merging — 통과와 반영을 벌리지 않는다

판정 통과 직후 같은 세션에서 반영합니다. 사이에 사람 대기·큐 대기를 두지
않습니다 — 그 사이에 기준선이 전진하면 판정이 썩습니다.

## 사람이 필요할 때

상한 소진·파괴적 조작·요구 모호는 전부 **의사결정 요청 문서**로 상신합니다.
메시지는 승인이 아닙니다 — 사람의 실제 응답이 착지해야 재개합니다.
